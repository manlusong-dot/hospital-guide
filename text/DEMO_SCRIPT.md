# 演示脚本

本演示脚本用于比赛现场展示"医院就医陪伴小程序"的核心功能。演示时长建议 10-15 分钟。

## 演示前准备

### 环境检查清单

- [ ] 安装 Ollama（https://ollama.com）
- [ ] 下载模型：`ollama pull qwen2.5:7b`（或 `qwen2.5:3b` 如果内存不足）
- [ ] 启动 Ollama 服务：`ollama serve`（后台运行）
- [ ] 安装 Python 依赖：`pip install -r backend/api/requirements.txt`
- [ ] 初始化数据库：`python backend/database/init_db.py`
- [ ] 启动后端服务：`python -m uvicorn backend.api.main:app --reload`
- [ ] 确认后端运行在 http://127.0.0.1:8000
- [ ] 打开微信开发者工具，导入 `frontend/miniprogram/` 目录
- [ ] 确认小程序能正常连接后端

### 演示设备要求

- 笔记本电脑（Windows/Mac/Linux 均可）
- 内存：至少 8GB（推荐 16GB）
- 硬盘：至少 10GB 可用空间
- 网络：无需联网（本地 Ollama）

## 演示流程

### 第一幕：智能导诊（3 分钟）

**场景**：用户牙疼，不知道挂什么科

**操作步骤**：

1. 打开小程序首页，展示"AI 就医助手"界面
2. 点击"智能导诊"标签
3. 在输入框输入："我牙疼两天了，晚上疼得睡不着"
4. 点击"开始导诊"
5. **展示结果**：
   - 系统推荐"口腔科"
   - 显示科室位置（3 楼）
   - 显示检查前注意事项
6. 点击"生成就诊流程卡"

**讲解要点**：

> "我们的系统采用双层匹配策略：第一层基于关键词规则，快速准确；第二层使用本地部署的大模型进行语义推理。整个过程完全在本地运行，无需联网，保护用户隐私。"

### 第二幕：就诊流程引导（3 分钟）

**场景**：用户按照系统引导完成就诊

**操作步骤**：

1. 展示就诊流程卡（12 步流程）
2. 点击"完成这一步"，推进到第 2 步"就诊前准备"
3. 展示当前步骤的注意事项
4. 继续推进 2-3 步，展示流程的连贯性
5. 点击"上一步"，展示回退功能

**讲解要点**：

> "就诊流程由确定性状态机驱动，12 步流程严格可控，不依赖大模型判断。这保证了流程的可靠性和一致性。用户可以随时前进或后退，系统会记住当前进度。"

### 第三幕：AI 对话答疑（3 分钟）

**场景**：用户在就诊过程中有疑问

**操作步骤**：

1. 切换到"对话咨询"标签
2. 输入："药怎么吃？"
3. 展示 AI 回答（不推进流程步骤）
4. 输入："下一步"
5. 展示流程推进到下一步
6. 输入："报告多久出来？"
7. 展示 AI 根据当前步骤回答

**讲解要点**：

> "系统能够智能识别用户意图：如果是步骤推进指令（如'下一步'），则推进流程；如果是问答类问题（如'药怎么吃'），则直接回答，不推进流程。这种分流机制确保用户在就诊过程中既能按流程推进，又能随时提问。"

### 第四幕：院内导航（3 分钟）

**场景**：用户需要去检验科做检查

**操作步骤**：

1. 在就诊流程中推进到"检查"步骤
2. 点击"带我去检验科"
3. 展示导航界面
4. 展示分步路线指引（如"前方左转"、"乘坐电梯到 2 楼"）
5. 展示"语音提示助手"开关（说明功能已预留）

**讲解要点**：

> "导航起点动态跟随就诊流程，以上一步的终点作为下一步的起点。比如从诊室到检验科，系统会自动以诊室为起点规划路线。这种链式导航无需用户手动设置起点，更加智能。语音播报功能已预留接口，授权插件后即可启用。"

### 第五幕：预约挂号（2 分钟）

**场景**：用户完成就诊，需要复诊预约

**操作步骤**：

1. 进入"预约挂号"页面
2. 选择科室（如"口腔科"）
3. 选择医生（展示医生列表）
4. 选择日期和时段（展示时段智能过滤）
5. 点击"确认挂号"
6. 展示挂号成功提示

**讲解要点**：

> "系统根据当前时间自动过滤已过时段。比如现在是下午 3 点，上午的时段就不会显示。这避免了用户预约已过期时段的问题。"

### 第六幕：就诊记录（1 分钟）

**场景**：用户查看历史就诊记录

**操作步骤**：

1. 在 AI 对话页面点击"就诊记录"
2. 展示历史就诊列表
3. 点击某条记录，展示详情

**讲解要点**：

> "每次就诊都有独立的档案，用户可以随时查看历史记录。系统会自动标记已完成的就诊，下次就诊时会创建新的档案，避免混淆。"

## 演示注意事项

### 常见问题处理

1. **AI 回答质量不高**
   - 原因：本地小模型能力有限
   - 应对：选择简单场景演示，强调"本地部署"的技术方案而非模型能力
   - 备选：如果演示机器性能好，可以换更大的模型（如 `qwen2.5:14b`）

2. **响应速度慢**
   - 原因：本地模型推理需要时间
   - 应对：提前预热模型（演示前先对话一次）
   - 备选：使用 GPU 加速（如果有）

3. **后端启动失败**
   - 原因：端口被占用
   - 应对：修改 `.env` 中的 `API_PORT`，或关闭占用端口的进程

4. **小程序无法连接后端**
   - 原因：后端地址配置错误
   - 应对：检查 `frontend/miniprogram/utils/config.js` 中的 `API_BASE`

### 演示技巧

1. **提前测试**：演示前至少完整走一遍流程
2. **准备备选方案**：如果本地模型效果不好，可以准备几个预设的截图或视频
3. **强调技术亮点**：
   - 本地部署，零成本，无 API Key 泄露风险
   - 确定性状态机，流程可控
   - 双层匹配策略，规则优先，大模型兜底
   - 链式导航，智能起点
   - 意图识别，问答分流
4. **控制节奏**：每个场景控制在 2-3 分钟，不要在一个功能上停留太久
5. **互动提问**：准备几个常见问题的答案，如"如何换一家医院"、"如何扩展科室"

## 演示后的技术问答

### 可能的问题及回答

**Q1：为什么使用本地模型而不是云端 API？**

> A：本地部署有三个优势：一是零成本，无需支付 API 调用费用；二是数据完全本地化，保护用户隐私；三是不依赖网络，演示更稳定。对于医院场景，数据隐私尤为重要。

**Q2：本地模型的准确率如何？**

> A：我们采用双层匹配策略：第一层基于关键词规则，对常见症状准确率达 100%；第二层使用大模型语义推理，处理复杂表述。核心流程由确定性状态机驱动，不依赖大模型判断，保证可靠性。

**Q3：如何扩展到更多科室？**

> A：只需修改 `backend/database/seed_data.py` 中的科室数据，重新运行 `init_db.py` 即可。系统会自动更新导诊规则和就诊流程。

**Q4：导航数据如何获取？**

> A：我们开发了 `map-annotator.html` 工具，可以在平面图上标注节点和连线，导出 JSON 格式。换一家医院只需重新标注地图，代码无需修改。

**Q5：语音功能为什么没有启用？**

> A：语音播报功能代码已完整实现，但需要授权微信同声传译插件。我们采用了优雅降级机制，插件不可用时自动切换为文字提示。正式部署时只需在小程序管理后台授权插件即可启用。
